How to read this page

The target dataset contains 700 “good” and 300 “bad” labels. Accuracy alone can hide missed bad-risk cases, so the project also reports bad-risk recall, balanced accuracy, and the dataset’s asymmetric error cost.

The final test set is held back from model and threshold selection. Its results are an estimate, not a guarantee; there are only 200 held-out rows.

    What the prototype does—and does not claim

    Design notes for a class demonstration.

    Dataset and target

    Statlog German Credit has 1,000 historical records and 20 input fields. The model predicts the dataset’s good/bad credit-risk label. UCI’s cost matrix assigns five times more cost to calling a bad-risk case “good” than the reverse.

    UCI dataset details and citation

    Evaluation guardrails

    • Stratified 80/20 train/test split.
    • Repeated stratified five-fold CV for model and feature-set comparison.
    • Threshold selected from training-only out-of-fold predictions using the dataset’s error costs.
    • Test set used once for final estimates, not for feature selection.

    Explainability limit

    For each prediction, the app replaces one selected field at a time with a typical training value and measures the score change. This is a sensitivity check, not a causal explanation and not SHAP attribution.

    Fairness limits

    The app reports group-level test rates for sex/marital-status, foreign-worker status, and age bands. Small subgroups have high uncertainty. These checks do not determine legal compliance.

    Audit and review

    Each demo prediction records the input values, output, threshold, model version, and local sensitivity notes in SQLite. Review actions are appended as hash-linked events so the chain can be checked for edits.

    Scope and privacy

    This is a local, educational prototype using an old benchmark dataset. Do not enter identifiable or real financial data. It has no authentication or production security controls and must not be used for lending decisions.
